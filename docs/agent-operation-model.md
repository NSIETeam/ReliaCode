# ReliaCode Agent 全操作模型

## 目标

ReliaCode 的每项业务能力都应同时提供页面入口和 Agent 能力入口。Agent 不通过模拟点击操作页面，而是调用与页面相同的领域函数和校验规则，因此页面操作与 Agent 操作产生一致的数据、不变量和审计记录。

“Agent 能完成所有操作”不等于 Agent 可以无条件自治。正确边界是：

- Agent 可以发现并调用当前系统的全部业务能力。
- Agent 的权限永远不高于当前登录账号。
- Agent 不允许切换、冒充或提升账号身份。
- 查询类操作可以自动执行。
- 改变业务状态的操作必须先展示结构化预览，再由当前用户确认。
- 付款、批量作废、活动正式发布等高风险操作在生产环境应进入双人审批，Agent 只能提交审批任务。

## 能力分级

| 风险等级 | 示例 | Agent 行为 |
|---|---|---|
| 低风险 | 打开页面、查询产品动向、验证可靠码、查看账本 | 自动执行并记录 Agent Run |
| 中风险 | 批量生码、聚合装箱、渠道收货、门店收货 | 展示参数、对象、组织和影响，用户确认后执行 |
| 高风险 | 风险通过/拒绝、奖励冲正、活动发布 | 展示影响与金额，本地优先版确认后执行；生产版应双人审批 |
| 禁止 | 切换账号、冒充他人、绕过单据、修改原始事件 | 拒绝执行并记录拒绝原因 |

## Agent Run

每次 Agent 操作均产生 `AgentRun`，至少包含：

- `id`：唯一执行号。
- `command`：用户原始指令。
- `capability`：调用的系统能力。
- `risk`：风险等级。
- `params`：经过解析和校验的结构化参数。
- `accountId/actor/deviceId`：当前账号、组织和设备。
- `status`：运行中、待确认、完成、失败、取消或拒绝。
- `approval`：自动执行策略或确认人。
- `result`：领域服务返回的业务结果。
- `createdAt/completedAt`：创建和结束时间。

相同 Run 进入完成、拒绝或取消终态后不得再次执行。生产服务还应为每个领域命令生成服务端幂等键。

## 当前已接入的 Agent 能力

- 页面导航和当前账号能力说明。
- 批量生成单品码、箱码或托盘码。
- 产品可靠码验证。
- 产品动向、奖励活动、账本和风险页面查询。
- 工厂聚合装箱。
- 渠道收货。
- 门店收货及后续奖励判断。
- 风险通过、拒绝或继续冻结。
- Agent 执行记录查询。
- 生码清单和工作区备份导出，以及本地工作区清除。
- 身份切换和越权请求拦截。

示例指令：

- `生成 1000 个全价成猫粮 2kg 单品码`
- `验证 <已生成的可靠码>`
- `查看产品动向`
- `通过风险 1`
- `门店收货 <已生成的可靠码>`
- `查看 Agent 执行记录`
- `导出最新生码清单`
- `导出工作区备份`

## 当前安全实现

- AgentRun、TraceEvent 和生码批次使用 UUID，不依赖毫秒时间戳。
- 写操作携带 `idempotencyKey`；相同键不会重复生码、重复写事件或重复处置风险。
- Agent 产生的业务对象记录 `agentRunId`、`source: AGENT` 和幂等键。
- 待确认任务保存于本地状态，刷新后可以继续确认或取消，15 分钟后自动过期。
- 当前账号变化会立即将原待确认任务标记为 `EXPIRED`。
- 领域函数内部再次鉴权，隐藏页面或按钮不是安全边界。
- Agent 抽屉关闭时使用 `inert`，支持 Escape、焦点约束和关闭后的焦点返回。

## 生产化要求

当前本地优先版使用本地规则解析中文指令并限定能力。生产版应把自然语言模型放在能力编排层，只允许模型选择经过注册的工具并填写结构化参数；真正的权限、业务校验、审批、幂等和事务仍由服务端领域层执行。不得让模型直接写数据库、拼接任意 SQL 或调用未注册接口。浏览器本地权限校验不能替代服务端数据库唯一约束、事务和审批服务。
