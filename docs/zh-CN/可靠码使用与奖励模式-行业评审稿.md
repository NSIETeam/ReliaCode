# ReliaCode（可靠码）使用与奖励模式

> 宠物食品行业评审稿 v0.1 · 用于业务机制评审，不是销售材料或最终产品承诺。

## 请专家重点评审什么

可靠码希望请有生产、经销、门店、供应链、食品安全或行业运营经验的人，重点验证五件事：现场是否做得动、扫码是否能证明真实业务、激励是否值得渠道参与、是否存在可规模化作弊方式，以及结算和数据边界是否可接受。

本稿暂不确定具体奖金金额、最终界面和供应商；这些应在试点数据和专家意见基础上迭代。

## 一页摘要

可靠码为每一袋宠物食品建立唯一数字身份，并记录单品、箱、托盘、批次及每次流转之间的关系。它解决的是：快速正反向追溯、召回定位、渠道可见性、窜货信号和门店触达。

可靠码的核心原则是：**奖励经过验证的业务行为，不奖励“扫到一个码”本身。** 例如，渠道商依据真实发货单完成首次收货，可进入奖励审核；同一个箱或袋的重复扫码、发货前扫码、消费者普通查询均不产生奖励。

首期建议只覆盖“工厂出货—渠道收货—门店收货”三类关键节点。奖励先以积分或企业应计余额运行，七天冻结、按月结算；不做店员个人即时现金奖励。

## 1. 适用范围与非目标

适用于袋装、罐装或盒装宠物干粮、湿粮和零食，尤其适合需要按袋追溯、按箱流转的商品。

可靠码不替代 ERP、WMS、MES、质检系统或防伪包装材料；二维码也不能独自证明商品物理真实或阻止所有造假。可靠码的作用是将编码、扫码、单据、库存和异常信号组合为可审计证据链。

## 2. 参与方、收益与数据边界

| 参与方 | 主要动作 | 获得的价值 | 默认可见范围 |
| --- | --- | --- | --- |
| 可靠码运营方 | 配置规则、审核异常、组织结算 | 全链追溯、召回、运营数据 | 全局，受岗位分权约束 |
| 工厂 | 生产赋码、质检放行、装箱、发货 | 减少手工台账，明确出厂去向 | 本工厂及被授权的订单 |
| 经销/渠道商 | 收货、调拨、拆并箱、退货 | 获得合规运营积分/权益，减少争议 | 本组织及授权网点 |
| 门店 | 收货、拆箱、上架、销售核验 | 获得运营激励与库存可信度 | 本门店及授权上级 |
| 消费者 | 查询单品来源与状态 | 产品信息、召回提示 | 仅公开商品信息，不显示渠道库存或奖励 |

可靠码运营方在试点中可以由商品经营主体或其授权团队承担，但系统术语统一使用“可靠码运营方”。

## 3. 码与包装层级

| 层级 | 标识 | 最低要求 | 用途 |
| --- | --- | --- | --- |
| 单品 | 单品码：SGTIN 或可靠码唯一序列号 | 一袋/一罐一个身份 | 精准追溯、召回、异常识别 |
| 箱 | 箱码：SSCC 或唯一物流单元码 | 每个物理箱唯一 | 装箱、发货、收货和箱级奖励 |
| 托盘 | 托盘码：SSCC 或等效唯一 ID | 托盘流转时启用 | 批量装卸与运输 |
| 批次 | 批次号、日期、效期、质检结果 | 与单品建立关联 | 质量控制与批次召回 |

装箱时，工厂逐个扫描单品，再扫描箱码，系统形成“单品属于该箱”的聚合关系。拆箱、换箱或破损重装必须先解除旧关系，再建立新关系；不能直接覆盖历史。

## 4. 标准作业流程

```text
生产赋码 → 质检放行 → 单品装箱绑定 → 工厂发货
       → 渠道收货 → 门店收货/拆箱 → 上架/销售核验
       → 退货、销毁或召回
```

| 节点 | 谁操作、扫什么 | 系统记录 | 是否建议首期计奖 |
| --- | --- | --- | --- |
| 生产赋码 | 工厂扫单品码 | 生产、批次、时间、工位 | 否 |
| 装箱 | 工厂扫单品码和箱码 | 单品—箱聚合 | 否 |
| 发货 | 工厂扫箱/托盘并关联发货单 | 发货、来源、目的地 | 否 |
| 渠道收货 | 渠道扫箱并确认发货单 | 首次有效收货 | 是 |
| 门店收货 | 门店扫箱或单品并确认调拨单 | 首次有效收货 | 是 |
| 拆箱/上架 | 门店扫箱/单品 | 拆箱、上架状态 | 第二阶段再评估 |
| 销售核验 | 门店 POS/进销存回传 | 销售证明 | 第二阶段再评估 |
| 消费者查询 | 消费者扫单品码 | 公众查询与风险信号 | 否 |

整箱未拆时，收货方扫箱即可确认其中的已知单品，不应要求再次逐袋扫码。出现破箱、少货、多货、混箱或抽检时，转为单品核验。

## 5. 四个常见场景

| 场景 | 正确操作 | 系统结果 | 是否计奖 |
| --- | --- | --- |
| 整箱正常收货 | 扫箱码，选择对应发货单并确认 | 验证箱状态与收货方，形成收货事件 | 符合活动时按箱首次计奖 |
| 拆零配送 | 先拆箱，再扫描分出的单品并建立新箱/门店关系 | 保留原箱历史与新聚合 | 不重复计算原箱已奖励单品 |
| 少货或错箱 | 扫箱和实际单品，提交差异原因及照片/单据 | 事件标记异常并进入审核 | 暂不计奖 |
| 退货 | 扫箱/单品并关联退货单 | 形成退货事件；按规则冲正 | 可产生反向账本分录 |

## 6. 奖励模式

### 6.1 首期推荐模式：首次有效收货激励

可靠码运营方创建活动时，选择参与组织、商品范围、区域、有效期、预算、每个箱或单品的奖励、每组织日/月上限、冻结期和退货冲正规则。

奖励成立必须同时满足：

1. 扫码者属于已审核渠道或门店，且有对应角色；
2. 商品已完成可靠码发货，并匹配发货单、目的地与活动范围；
3. 当前组织是第一个有效收货方；
4. 箱—袋关系与库存状态正常，未在同一活动中计奖；
5. 未命中需要人工审核的风险规则。

### 6.2 可选激励类型

| 模式 | 适合的业务目标 | 建议奖励对象 | 上线优先级 |
| --- | --- | --- | --- |
| 收货积分 | 提升渠道/门店收货扫码率 | 签约企业或门店主体 | 第一阶段 |
| 及时性奖励 | 缩短到货确认时间 | 企业或门店主体 | 第一阶段后半段 |
| 陈列/上架任务 | 提升门店执行质量 | 门店主体 | 第二阶段 |
| POS 销售核验 | 提升销售可见性 | 门店主体 | 第二阶段 |
| 消费者权益 | 提升复购或互动 | 消费者 | 独立评估后实施 |

首期避免“每扫一袋即现金奖励”。这会激励重复扫描而不是正确收货，也会带来个人收入、税务、支付和利益冲突问题。

### 6.3 示例

某活动设定：指定区域的门店，在收到可靠码已发货的猫粮后，24 小时内首次有效扫描箱码，每箱获得 100 积分；每个门店每月最高 10,000 积分；冻结期 7 天。若该箱随后确认退货、错发或异常，则以负 100 积分冲正，而不是修改原记录。

## 7. 结算与争议处理

奖励经历：`待验证 → 待审核/已拒绝 → 已应计 → 已结算 → 已冲正`。

- 规则发布后按版本冻结；改规则只影响后续扫码。
- 使用最小整数单位记录积分或金额；禁止直接改余额。
- 高风险、退货未过冻结期或资料不全的奖励进入暂缓。
- 每月生成锁定的结算批次、对账单和失败重试记录。
- 渠道和门店可在规定期限提交申诉；申诉、审核、人工调账和结算均保留操作者、原因和证据。

真实现金、红包、银行卡付款或代付上线前，必须由法务、财税和支付服务方确认规则，不应由可靠码自建资金池。

## 8. 防刷与异常处理

可靠码将“扫码正确”与“奖励成立”分开。除二维码外，系统还应交叉验证组织、用户角色、设备、发货单、库存、箱袋关系、服务端时间和上下游事件顺序。

重点风险包括：复制码反复扫、发货前扫、同箱袋重复领奖、多人共用账号、一个设备切换大量组织、扫描速度异常、跨区域串货、离线乱序上传和退货后仍领奖。

处理原则：低风险直接通过；中风险冻结奖励并补充材料；高风险拒绝并保留申诉入口。GPS 仅是风险信号，不能作为真实交接的唯一证据；离线扫码只能生成待验证记录，联网校验后才能计奖。

## 9. 权限、隐私与数据

- 可靠码运营管理员配置活动，不能直接修改账本；风控、财务、客服相互分权。
- 渠道和门店仅能看到自身组织和授权网点的数据。
- 手机号、定位、付款和身份资料遵循最小必要原则；明确收集目的、保存期限、访问和删除路径。
- 对活动参与、个人信息、定位、税务、商业利益冲突、支付和数据出境的具体要求，应由相关法务与财税顾问在上线前确认。

## 10. 试点建议与验收指标

建议从一个商品经营主体、一个工厂、少量经销/渠道商和门店开始。试点不追求全链覆盖，而验证三件事：箱袋聚合是否准确、收货扫码是否自然、激励是否提升有效事件比例。

| 指标 | 含义 | 建议观察方式 |
| --- | --- | --- |
| 赋码成功率 | 合格单品是否拥有唯一身份 | 产线记录与抽检 |
| 聚合准确率 | 实物箱与系统箱内单品是否一致 | 装箱抽检和收货差异 |
| 收货扫码率 | 已发货单中完成首次有效收货的比例 | 发货单与事件对比 |
| 每箱操作时长 | 是否影响现场节拍 | 工位/门店抽样 |
| 异常与申诉率 | 风控误伤及流程问题 | 风险和客服记录 |
| 奖励成本/有效收货 | 激励是否有效率 | 活动预算与有效事件 |
| 召回定位时间 | 能否快速找到受影响单品和持有方 | 演练计时 |

## 11. 请行业专家回答的关键问题

1. 首期哪些 SKU 值得单品序列化，哪些仅需批次或箱级追踪？
2. 工厂出库、渠道收货、门店收货三个节点是否足以形成第一阶段价值？
3. 混箱、拆零、二级分销和跨店调拨在实际业务中的比例与处理方式是什么？
4. 门店扫码应由店主、店员还是企业账号承担？人员变动后权益归谁？
5. 可靠码首期最优先解决召回、渠道可视、窜货还是门店运营？
6. 单品码应使用明码、隐藏码还是双码？成本、作业和消费者体验如何权衡？
7. 一个箱是否允许混 SKU 或混批次？若允许，现场标签和召回如何执行？
8. 奖励应给企业、门店还是个人？可接受的积分、货补、返利或现金形式是什么？
9. 哪个事件最能代表真实价值：收货、拆箱、上架还是销售？
10. 每个有效收货的可接受成本上限、冻结期和月度封顶应是多少？
11. 退货、冲红、跨店调拨和活动结束后的奖励如何冲正？
12. 共享设备、PDA、扫码枪和 API 自动上传是否允许，责任由谁承担？
13. 渠道愿意开放到什么粒度的库存与门店数据？
14. 可靠码不可用或弱网时，生产与收货能否继续，补传时限多长？
15. 试点扩张与停止的前三项量化门槛是什么？
