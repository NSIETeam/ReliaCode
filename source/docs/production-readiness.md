# ReliaCode 生产化基线与上线门槛

## 当前结论

仓库已经具备可持续生产化的服务端基线，但不能仅凭代码合并就宣称“已生产上线”。生产环境还必须完成真实 OIDC、托管 PostgreSQL、OpenEPCIS、监控告警、备份恢复演练、安全测试和业务试点验收。

`scan-web` 的 GitHub Pages 模式从空白工作区开始，不包含任何预置业务记录；它仍不是多人生产数据源。生产写操作必须经过 `scan-api`，数据库是唯一事实来源。

## 已落实的技术控制

- PostgreSQL 租户、组织、产品、序列对象、发货单、追溯事件、活动版本、Claim、追加式账本、风险和审计模型。
- PostgreSQL 使用租户与受信系统双连接池；受信角色由迁移所有者登记在不可由运行角色修改的注册表中，RLS 系统访问同时验证数据库角色和事务 GUC，租户角色无法伪造系统上下文。无租户列的平台审计、申请、恢复和备份表使用仅系统角色可访问的强制 RLS。
- 密码登录限速使用 PostgreSQL 共享原子状态，不依赖单进程内存；网络与账号标识都先经 keyed HMAC，表中不保存用户名或 IP 明文。跨实例第五次失败进入五分钟阻断，不存在账号仍执行等成本的 scrypt 校验。
- 追溯事件、账本、审计日志禁止 UPDATE/DELETE；撤销通过反向事件或反向分录实现。
- 应用内账号与 Passkey/WebAuthn、可选 OIDC JWT、角色能力表和服务端租户/组织范围校验；正式生产拒绝开发身份模式及无数据库身份的共享 `local-admin`。平台运营、租户所有者和品牌管理员必须注册至少两个 Passkey，敏感写操作要求近期 Passkey step-up。
- 所有写接口要求 `Idempotency-Key`，同键不同请求会返回冲突。
- 行级锁与事务保护码状态迁移、发货单校验、活动预算/月封顶、Claim 和账本一致性。
- 业务单据审批前必须列出至少一个预期序列对象；明细保存加入时快照，审批后不可修改，状态事件必须同时通过单据类型、状态、作业组织和对象明细校验。
- 单据对象区分待履约 `ACTION` 与授权上下文 `CONTEXT`；事件只能消费一次动作行，首条履约自动进入执行中，全部预期动作行履约前不能完成单据。
- 生产 Web 已提供领域 API 单据控制台和游标分页事件中心；组织、单据明细、审批版本与事件筛选均由租户范围服务端接口提供，不再依赖浏览器工作区事实。
- 生产 Web 已提供租户范围风险处置和召回控制台；风险决定与召回激活具备 CSRF、幂等、审计和签名 Webhook，召回激活会冻结当时命中的对象范围并拒绝空范围。
- CASE/PALLET 状态动作在事务内递归展开当前子件，逐件验证并原子流转；事件对象快照表追加保存当时的包装树和前后状态，后续换箱不改写历史证据。
- 装箱/拆箱要求父子对象同时存在于包装单据，OpenEPCIS 使用 `AggregationEvent ADD/DELETE` 表达聚合关系，不再把包装关系错误表示为普通 `ObjectEvent`。
- 换箱由单个 `REPACKING` 命令原子完成：锁定旧/新父箱，验证三方单据范围，一次改父键并追加旧关系删除、新关系增加及双 OpenEPCIS 聚合事件，禁止客户端两步换箱造成悬空状态。
- 事务性 outbox；OpenEPCIS 不可用时不丢失已接受的业务事件，后台指数退避重试。
- 请求大小、速率限制、CORS 白名单、安全响应头、敏感日志脱敏、健康检查和优雅停机。
- API 入口支持 OpenTelemetry OTLP/HTTP 自动追踪；未配置收集端时保持关闭，生产配置拒绝明文 HTTP 收集端。
- 正式生产必须连接 HTTPS OTLP 收集端；鉴权 headers、指标令牌、Webhook 加密主密钥和会话指纹密钥只能通过单行只读 secret 文件注入，发布预检拒绝非 `0400/0600` 权限。
- 正式生产部署在配置层拒绝数据库明文连接、不安全 Cookie、非 HTTPS 浏览器及外部服务地址和非 SMTPS 邮件传输；单机 IP 试点必须使用独立 `pilot` 环境标识。
- Docker Compose 网络隔离、数据库持久卷、容器健康检查和迁移前置任务。
- 单元/API/E2E/移动端/Agent 测试与 GitHub Actions 依赖漏洞审计。
- Web 回归套件自行分配隔离端口并管理测试服务器，不依赖或复用固定本机端口，避免并行 Agent、CI 或残留服务造成假阳性。
- API 与 Web 镜像都注入完整 Git SHA；正式 API 拒绝版本与 SHA 不匹配的构建，发布及回滚只有在两端健康响应精确报告同一目标 SHA 时才成功。
- 每个序列对象具备独立公开验证 UUID；匿名验证接口执行字段最小化，二维码可直接打开验证网址。
- 手机摄像头优先使用原生二维码检测，并以内置本地解码器兼容不支持 `BarcodeDetector` 的浏览器。

## 上线前硬门槛

1. 身份：完成一次性真实平台运营账号初始化并删除初始密码文件；平台运营和品牌管理员注册至少两个 Passkey、生成恢复码并验证会话撤销。若租户选择外部身份提供商，则使用授权码 + PKCE。关闭本地账号切换和浏览器数据清除入口。
2. 数据：使用托管 PostgreSQL 多可用区实例，启用 TLS、时间点恢复、每日备份和至少一次恢复演练。
3. 主数据：导入真实组织、网点、SKU、GTIN/GLN、设备和业务单据；清理所有开发种子。迁移 `021_gs1_master_data.sql` 会将校验位无效的活动产品/网点降级为非活动状态，上线前必须修正并由业务负责人复核后再启用。
4. 编码：逐租户核验 GS1 Company Prefix 的合法分配证明，再由租户所有者录入；逐产品核对 ITEM 与 CASE 使用各自获配的 GTIN，抽检 AI (01) SGTIN、AI (10) 批号、AI (21) 序列号与 AI (00) SSCC 的长度、字符集、校验位、路径顺序、唯一性和解析结果。当前 `urn:reliacode:*` 仅是兼容占位命名空间，不得用于新生产码。
5. OpenEPCIS：对目标版本完成 capture/query 合同测试，验证拆箱、换箱、退货、乱序和重复事件。
6. 安全：SAST、依赖扫描、DAST、越权与租户隔离渗透测试全部通过；密钥只进入密钥管理服务。
7. 可观测：集中日志、指标、追踪、数据库连接池、outbox 积压、错误率和 P95 延迟均有告警及值班联系人。
8. 奖励：现金或企业返利上线前完成合同、税务、反商业贿赂、支付和个人信息专项审查。
9. 容量：按真实峰值完成扫码并发、百万级码批次异步生成和批量导出压测。生产生码已使用独立后台作业与对象存储导出，但仍须在目标基础设施上验证百万级任务、worker 重启和失败恢复。
10. 灾备：定义 RPO/RTO，完成 API、数据库、对象存储和 OpenEPCIS 的故障演练。

## 推荐发布门槛

- 所有 P0 业务旅程通过，重复提交不产生第二事件、Claim 或账本分录。
- 跨租户和跨组织读取、写入均返回 403/404，不泄露对象存在性。
- PostgreSQL 主库切换、API 重启、OpenEPCIS 停机时不丢事件。
- 关键接口 P95 小于 500ms（不含批量生码/导出作业），错误率低于 0.1%。
- GitHub `performance` Environment 只连接隔离压测租户，目标 API 必须显式配置 `DEPLOYMENT_ENVIRONMENT=performance`，否则脚本在任何写入前失败。手动运行 `production-scale-gates` 的三个门禁：`scan` 至少 30 次/秒并验证幂等、P95 <500ms、错误率 ≤0.1%；`million-codes` 必须生成恰好 1,000,000 个码并完成带 SHA256/大小元数据的对象存储导出；`ten-million-query` 会先验证数据库角色无写权限、无建库/建角色、非超级用户且无 `BYPASSRLS`，再证明租户事件数不少于 10,000,000 并验证公共履历查询 P95 <500ms。不得对真实客户租户运行写入型门禁。
- `security-analysis` 在主分支、PR 和每周计划中运行 CodeQL `security-extended` 与全 Git 历史 Gitleaks；Gitleaks 下载包校验官方 SHA-256。`dast` 只允许通过 `security-test` Environment 手动指向隔离 HTTPS 环境，使用固定的 ZAP 2.17.0 amd64 镜像摘要并在任何未基线化告警时失败。DAST 不是租户越权渗透测试的替代品，后者仍需独立签字报告。
- outbox 正常积压小于 1 分钟，超过 5 分钟告警。
- 备份恢复演练和召回演练都有签字记录。

## 明确不在当前代码中完成的外部事项

- 真实身份提供商租户及客户端配置。
- 云数据库、域名、TLS 证书、WAF、密钥管理和监控账号。
- 持牌支付、发票税务、短信/微信登录和消费者红包。
- 品牌方 ERP/WMS/MES 的具体字段映射和数据治理。

这些事项依赖品牌方选择和外部系统权限，不能由仓库代码安全地替代。
