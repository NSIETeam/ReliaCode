# ReliaCode（可靠码）运营端设计规范

## 1. 产品定位

可靠码运营端服务于宠物食品流通过程中的工厂、渠道与门店。它不是泛化的“后台”，而是让操作人员在几秒内判断一件事：**这次扫码是否真实、是否能收货、是否会产生奖励、是否需要处理异常。**

页面必须始终分清两类信息：

- **追溯事实**：码、箱袋关系、发货单、组织、时间与货物状态。
- **奖励判断**：活动规则、资格、冻结、风控、结算与冲正。

## 2. 设计原则

1. 先判断，再操作：每页首先显示当前对象、状态和下一步，而非密集表格。
2. 事实与钱分离：追溯成功不自动等于奖励可用；奖励状态必须单独显示。
3. 风险优先：错误、重复、串货和异常顺序使用醒目的风险色与明确原因，不能静默失败。
4. 一次只做一件事：收货页只完成收货；活动页只配置规则；账本页只对账和追溯来源。
5. 现场优先：PDA 与手机宽度下，扫码输入、状态和主按钮不横向溢出，且主操作不被遮挡。

## 3. 信息架构

| 模块 | 操作目标 | 首屏必须回答的问题 |
| --- | --- | --- |
| 运营总览 | 处理当日待办 | 今天有什么收货、风险、冻结与可结算金额？ |
| 扫码收货 | 验证并确认流转 | 此码属于哪张发货单？箱内多少袋？能否收货和计奖？ |
| 奖励活动 | 配置运营规则 | 哪些组织/商品/时间/事件可奖？奖励、上限和冻结期是多少？ |
| 奖励账本 | 查看和对账 | 每笔奖励来自什么业务事实，现在处于何种状态？ |
| 风控待审 | 处理异常 | 命中了什么规则、证据是什么、处置会改变什么奖励状态？ |

## 4. 视觉系统

- 主色：可靠蓝 `#246BDE`，用于主按钮、选中状态和可点击动作。
- 深色导航：`#0D2342`，用于组织级工作台的稳定边界。
- 成功：`#15856B`；警示：`#C77900`；风险：`#BF4545`。颜色必须和文字状态同时出现。
- 正文：`#132238`；次级说明：`#6D7B8F`；分割线：`#E5EAF0`。
- 字体：中文使用 Microsoft YaHei，英文与数字使用 Calibri/系统无衬线；金额、编码使用等宽字体或加粗。
- 间距：8px 基准；卡片内边距 20px（手机 16px）；页面模块间距 16px。

## 5. 页面结构规则

### 顶部上下文

所有页面展示当前组织、角色、工作地点、环境和数据更新时间。演示/试运行/生产状态须明确，不能把本地数据展示为共享后台。

### 状态卡片

最多四个，数值必须由当前数据聚合得出；不得使用固定的“+18%”“500”“0”等占位统计。每张卡说明该数字的业务含义与下一步。

### 表单

表单字段必须有可见标签、默认业务值和单位；不以仅有 placeholder 的空输入框承载关键信息。活动配置至少含名称、商品范围、参与组织、触发事件、计奖层级、奖励、日/月上限、冻结期、结算周期和有效期。

### 表格与列表

列表项使用“对象 + 状态 + 结果 + 时间”结构。手机端隐藏非核心列，保留编码、状态、金额和操作；编码可以换行但不可截断。

## 6. 关键交互

### 收货扫码

1. 展示选中的发货单、发货/收货组织、预计箱数和当前进度。
2. 输入或扫描箱码后，先返回箱内单品数量、批次和匹配结果。
3. 验证成功后写入一条追溯事件，再创建独立奖励申请；页面同时给出事件号和奖励状态。
4. 重复码、非本单码、已拆箱、发货前扫码或跨组织扫码必须显示具体原因和下一步。

### 奖励活动

活动以草稿保存。发布后规则版本冻结；编辑规则创建新版本，既有奖励保留原版本。界面用完整表单展示真实默认范围，而不是“待配置”。

### 风控与账本

风控处置保留状态、处置人、时间与备注；通过、拒绝、继续冻结不能删除追溯事实。账本仅追加，冲正显示为负数和关联原因，不直接改历史余额。

## 7. 可访问性与质量门槛

- 所有可操作控件有文字名、焦点状态和键盘可达性。
- 结果区域和 toast 使用 `aria-live`，不只依赖颜色。
- 输入值经转义后再渲染；活动名称、组织和码不可插入 HTML。
- 320px、375px、桌面三种宽度无横向页面溢出。
- 演示环境的每一个可见统计、活动、发货单、箱码、风险与账本记录都必须来自本地结构化数据，而不是空白或“待配置”文案。
