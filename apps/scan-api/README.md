# ReliaCode Scan API

生产写入边界，负责身份验证、租户隔离、码资产、流转事件、风险处置、奖励账本和审计。所有写接口必须携带 `Idempotency-Key`，追溯事件、账本和审计表由数据库触发器保证追加式保存。

核心租户表启用并强制 PostgreSQL RLS。API 使用异步请求上下文在每个事务中设置 `reliacode.tenant_id`；生产连接角色不得是超级用户或具有 `BYPASSRLS`，否则就绪检查失败。系统上下文只用于认证、消费者公开投影、平台控制面和后台 worker，不能由租户请求继承。

本地开发：

```powershell
npm install
$env:DATABASE_URL='postgres://reliacode:reliacode@localhost:5432/reliacode'
$env:AUTH_MODE='development'
npm run migrate
npm start
```

开发身份通过 `X-ReliaCode-Principal` JSON 请求头提供；`NODE_ENV=production` 时服务会拒绝 development 身份模式，必须配置本地账号或 OIDC。生产环境使用本地账号时必须同时配置 SMTP、发件人和账户恢复页面地址。

公开产品验证端点为 `GET /api/public/v1/objects/:publicId`。该端点无需身份令牌，使用不可枚举 UUID、IP 速率限制和最小化响应；不会返回租户、组织、人员、设备、单据、奖励或内部对象 ID。生产环境应只允许受控的公开验证前端 Origin，并在 CDN/WAF 层增加滥用防护。

生产生码使用 `POST /api/v1/code-jobs`，审批后由 `worker:codes` 分块生成。产品 GTIN 和网点 GLN 在 API、旧数据导入和数据库约束三层执行 GS1 Mod-10 校验；无效的存量活动主数据在迁移时安全降级为非活动状态。单品与箱级贸易项目分别维护独立 GTIN，租户内不可重复；已有产品 GTIN 只回填为 ITEM，缺少 CASE GTIN 时箱码任务会在占用额度前被拒绝，已产生任务的层级 GTIN 不允许更换。新生成的 GS1 Digital Link 使用数字 AI，GTIN-8/12/13 会补零为规范的 14 位 AI (01) 值；批号使用 1–20 个 GS1 XCHAR，并按规范百分号编码到 AI (10)，路径顺序固定为 (01) → (10) → (21)。数据库 `NOT VALID` 约束保留历史不合规批号供审计，但拒绝新写入。托盘使用 18 位 SSCC AI (00)：租户所有者先配置本企业 GS1 Company Prefix，审批事务锁定租户设置并预留不可复用的连续引用号段，任务保存前缀和起始号快照；首次 SSCC 分配后前缀不能在线更换。迁移前已有的 PALLET+SGTIN 任务会标记为非合规遗留并禁止继续生成。完成后 `worker:code-exports` 以固定内存分页生成 UTF-8 CSV、分片上传到 S3 兼容对象存储并保存 SHA-256；`GET /api/v1/code-jobs/:id/download` 只为当前租户签发 5 分钟下载地址，不通过 API 进程传输文件。对象存储凭据必须通过文件型 secret 注入，导出失败十次后进入死信并由有审批权限的管理员审计重试。

生产业务事件强制使用已注册设备。设备注册要求绑定同租户、同组织的活动网点，网点必须具备校验位有效的 GLN；一次性设备令牌只在首次响应显示，数据库仅保存哈希，幂等重试不会重新泄露令牌。事件请求通过 `X-ReliaCode-Device-Id` 和 `X-ReliaCode-Device-Token` 认证，设备必须处于活动状态且获准执行对应事件类型。服务端从设备绑定网点生成 AI (414) GS1 Digital Link 读取点并写入事件，忽略客户端自报位置；撤销设备后后续作业立即统一返回未授权。开发环境可显式关闭该门禁，生产 Compose 固定启用。

状态变化事件必须引用已批准或执行中的业务单据。单据在 `DRAFT` 状态通过 `POST /api/v1/documents/:id/objects` 添加预期序列对象，通过 `DELETE /api/v1/documents/:id/objects/:objectId` 删除误录明细；每条明细保存加入当时的对象快照，且两种修改均要求幂等键和审计理由。空单据不能审批，审批后明细被冻结；事件对象不在单据中或被标记为非预期时返回 `OBJECT_NOT_ON_DOCUMENT`，不会写入追溯事件。跨租户单据、对象和明细统一按不存在处理。

本地账号会话默认每 15 分钟轮换令牌和 CSRF，IP 只以 keyed HMAC 保存，不落原始地址。密码、Passkey 和恢复码登录都会写入追加式 `authentication_events`；网络与浏览器同时变化时标记为高风险，并通过 `reliacode_risky_logins_24h` 告警。租户所有者和品牌管理员必须注册至少两个 Passkey；敏感管理写操作还要求当前会话在最近 10 分钟内完成真实 Passkey 验证，密码或恢复码登录不能绕过该门禁。用户可查看设备会话、识别当前设备、按设备远程撤销或一次撤销其他全部设备；撤销命令具有租户与用户双重边界、幂等记录及认证事件。租户管理员可冻结非所有者成员，平台运营可暂停整个租户；冻结操作会立即撤销相关会话并保留理由。

Passkey 可由用户在设备管理界面撤销，撤销操作要求近期 Passkey 验证、幂等键并写入审计；管理员撤销后至少保留两个 Passkey，其他账号至少保留一个，防止误操作锁死账户。恢复码轮换同样要求管理员近期验证和至少两个 Passkey。每批恢复码只显示一次、数据库只保存哈希；事务性发行记录保证同一幂等键的网络重试不会生成第二批，重复请求返回“已发行但不能再次显示”。

已验证邮箱可申请单次、限时的密码重置链接。接口对未知、未验证和已验证邮箱返回相同结果，数据库只保存令牌哈希；重置成功后会在同一事务内撤销该账号的全部会话并记录认证事件。邮箱验证令牌与密码重置令牌用途隔离，发送内容为纯文本链接。

平台人工复核恢复使用独立工单：一名平台运营发起，另一名运营审批，发起人不能自批。批准时只返回一次 30 分钟有效的恢复凭据，数据库保存其哈希；完成恢复会原子更新密码、消费工单、撤销全部会话并写入高风险认证事件。该凭据必须通过合同约定的受控渠道交付，不能出现在工单列表、日志或邮件模板中。
